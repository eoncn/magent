## 本轮判定（不要宣称性能收益）

| 指标 | 旧版 | 新版 | 解释 |
| --- | ---: | ---: | --- |
| 有效任务配对 | 20 | 20 | 每个版本各运行 20 次，CSV 记录全部 pass |
| 验收通过数 | 20 | 20 | 质量不退化，但并非统计显著 |
| 平均活跃时间 | 264.1s | 309.6s | 新版多 45.5s/案例，约 +17.2%，不能归因于模型 |
| 已知修复重试总数 | 2 | 5 | 样本本身未证实效率改善 |
| 19 个完整 token 配对累计（输入+输出） | 10,327,718 | 11,713,542 | 新版多 1,385,824（约 +13.4%），包含缓存输入、不是账单成本 |
| 新版 M 初始路由 | — | routine 8/8 | 未选择 standard（Terra） |
| 新版 H 初始路由 | — | high 4/4 | 高风险分类成功，但不足以证明性能改善 |

耗时样本里新版 13/20 更慢、7/20 更快；H03 涉及操作者 900 秒墙钟中断与同会话恢复，且缺失完整 token，不适合单独作性能因果推断。样本按大小 S=8、M=8、H=4，仅为一次性合成标准库任务，每个版本每题运行一次。

**结论分层**：

- **功能正确性（候选测试范围内）**：报告支持 old/new 均 20/20 PASS；未报告未验收先 PASS、越界修改或外部 Claude 意外开启。
- **长任务稳定性**：报告支持新版 3 阶段 task_id 新会话续跑、closed 防护、revision 冲突拒绝、retry_count=7 拒绝；旧版依赖同会话 resume。专门故障注入观察到 routine Luna → standard Terra 升级与独立 Verifier PASS。
- **Terra 常规开发能力**：**没有被本次正式 M 质量评测覆盖**。8 个 M 案例新旧首次路由均为 routine，且报告指出正式质量运行中没有 standard Worker。故障注入只能证明 Terra 可调用/升级通路可用。
- **性能、用量与费用收益**：本轮不支持“已优化”“更省额度”“更快”结论。不能把主会话与直接子会话 input+output 合计简单等同账单/订阅用量。中断运行未完整计费，不得填零。
- **测试覆盖缺口**：没有真实业务返工任务、没有触发自动 compaction、没有 Sol 层持续失败穷尽测试、没有在 Python 3.9 环境复核 H03 夹具迁移实现。

## 保守最终收敛：不改生产调度参数

1. **保留** Luna routine xhigh、Terra standard high、Sol high、routine/high Verifier 和既有主 Agent 长任务协调职责。
2. **保留**独立只读 Verifier、每里程碑最大六次修复、有界失败升级、外部 Claude 首参数 opt-in，以及原 CCB/安装/同步代码。
3. **暂不更改**模型路由阈值、Luna effort、Verifier 模型、主 Agent 模型或自动触发第二次/第三次审核。新方案已经验证可用，但没有证据说明更改能减少成本或改善成功率。
4. **修订评测工具与文档**，让 M 类 standard 首次路由覆盖度、缺失 token 数量、已知 retry 样本数量显式呈现；这些是报告准确性优化，不是模型性能优化。
5. **后续试验必须隔离成单独候选**：可在本地另建实验配置，显式把具备多模块协调、契约交互、中等调试的 M 类优先交给 Terra，对照 routine Luna；不得直接宣称 Terra 更高效或修改当前稳定默认。先做 4～8 个同 prompt、同基线、同主 Agent、固定 verifier、成对交错的小样本；再决定是否扩大范围。

## 原始证据的边界

此复盘仅收到四份 Markdown/CSV 摘要文件，未收到 stage3-report.md 提到的 runs/、policy-audit.json、environment.json、fixture-repositories.tar.gz 或完整 prompts/。因此不能独立复核 40 次 CLI 运行日志、原始 token 事件、SHA/验收文件是否真的冻结、Reviewer/Verifier 调用或中断开销。报告中的这些结论属于**操作者记录并已自洽的结果**。

原始 H03 的有效结果为 resume 后的同一任务延续，不是同基线重新开始的第二次质量样本；其缺失 token 必须继续留空。旧/新版 H02 跨服务额度恢复窗口，不宜据时长排序模型。所有有效 CSV 行按相同 model/effort 主会话设定（报告：gpt-6.1-sol/high，Codex CLI 0.164.0）执行，但服务负载不受控制。
